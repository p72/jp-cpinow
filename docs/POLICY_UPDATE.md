# 政策表（scripts/policy.csv）の週次更新手順

毎週の定期タスク（Claude）と、手で更新するときの両方がこの手順に従う。
目的は、**予測に効く政策・制度の新しい決定を、発表日つきで漏れなく `scripts/policy.csv` に入れること**。

## 1. 調べる対象（予測期間＝最新の公表月の翌月から3か月先まで＋その先の数か月）
| 項目 | kind / leaf | 主な一次情報 |
|---|---|---|
| 電気・都市ガスの料金支援（値引き単価、対象の使用月） | `subsidy_elec` / `subsidy_gas` | 資源エネルギー庁の特設サイト [https://denkigas-gekihenkanwa.go.jp/](https://denkigas-gekihenkanwa.go.jp/)、経済産業省の報道発表、大手電力・ガス会社のお知らせ |
| ガソリン・灯油の補助（上限目安の変更・終了、支給単価） | `cap` / gasoline | 資源エネルギー庁「燃料油価格定額引下げ措置」、経済産業省の報道発表 |
| 再エネ賦課金（毎年3月ごろに翌年度の単価を発表） | `levy` / electricity | 経済産業省・資源エネルギー庁の報道発表 |
| 税制・無償化・公共料金など CPI を階段状に動かす制度 | `event` | 各省庁・自治体の発表（たばこ税・酒税、授業料・給食費の無償化、携帯料金、上下水道料、診療報酬 など） |

ニュース記事は手がかりとして使い、**単価や適用月は必ず一次情報（省庁・事業者の発表）で確認**する。

## 2. 書き方（列の意味は policy.csv 冒頭のコメントを参照）
- `start` / `end`：**CPIに反映される月**（YYYY-MM）。電気・ガスは検針月＝使用月の翌月。例：「2026年11月使用分」→ CPI の 2026-12。
- `value`：電気は円/kWh（低圧）、都市ガスは円/m3、ガソリン上限は円/L、`event` は前月比インパクト（%、分からなければ空欄）。
- `announced`：**決定・公表された日**（閣議決定日、報道発表日）。バックテストではこの日以降しか使わないので、推測で早めの日付を入れないこと。
- `region`：全国／東京（東京都だけの施策は「東京」）。
- `scenario`：決定済みは `base`。「検討中」「報道ベース」は追加しない。
- `note`：日本語で短く。`source`：一次情報のURL。
- 既存の行と重複させない。訂正は既存行を直す（`announced` は元の決定日のまま）。

## 3. 反映と確認
```bash
python -m pytest -q tests                               # 書式の検査
python -c "from scripts import policy; import pandas as pd; print(policy.assumptions(pd.date_range('YYYY-MM-01', periods=3, freq='MS')))"
```
`policy.assumptions` の文が、新しい決定を反映した内容に変わっていることを確認する。

## 4. 定期タスクの出し方
- 変更があるときだけ、ブランチ `policy/YYYY-MM-DD` を作って **Pull Request** を出す（`main` には直接 push しない）。
- PR の本文には、追加・修正した行ごとに「何が決まったか・発表日・一次情報のURL」を書く。
- 変更が無ければ何もしない（PR もコミットも作らない）。
